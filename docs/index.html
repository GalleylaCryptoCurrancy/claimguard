ClaimGuard

An Agent ID-gated safe-claim registry for autonomous agents on BNB Chain.

The problem. Autonomous agents now claim value-bearing opportunities — red packets, mints, airdrops — on behalf of their owners. That is exactly where scam contracts and drainer previews strike: one bad claim can empty a wallet, and today an agent's safety decisions leave no public trace.

The product. ClaimGuard lets any Agent ID holder register a hash of their agent's safety policy on-chain, then write an attestation for every safety-gate evaluation their tooling performs: PASSED when all gates were green and the claim proceeded, REFUSED — with a machine-readable reason code — when a gate stopped it. The result is a public, auditable trail of what an agent claimed, and what its safety gates refused.

How Agent ID is used

  • Registration is gated by Agent ID. registerAgent(policyHash) checks the caller's balance in the official Agent ID registry (0x60B9262456dE011F7d15a54CdD8c48bAaa8B022F) and reverts for non-holders. Agent ID is not a badge on the page — it is the access key to the registry.
  • Attestations are keyed to the agent's address, so an Agent ID holder's safety record is publicly readable via isRegisteredAgent, agentPolicy and the ClaimAttested event stream.
  • The reference integration is Agent-ID-native: ClaimGuard's monitor watches agentid.im red packets, which are claimable only by Agent ID holders, and attests every gate outcome for them.

The safety gates (fail-closed)

Helper-only calls. The monitor only ever executes calls produced by the audited claim helper — never hand-built calldata.
Exactly one call. A claim must resolve to a single contract call; anything else is refused (reason UNEXPECTED_CALL_SET).
Exact preview match. The signed preview must name the expected contract and the exact incoming asset, with value 0 — mismatches are refused (PREVIEW_TARGET_MISMATCH, PREVIEW_VALUE_NONZERO).
Standard assets only. Custom-token opportunities are refused and reported, never auto-claimed (CUSTOM_TOKEN).
Human-held codes. Code-gated opportunities wait for a human-supplied code instead of guessing (CODE_REQUIRED).
Asset-free registry. The ClaimGuard contract holds no funds, has no payable functions, requests no approvals, and has no owner or admin functions at all.

Register your agent

  1. Hold an Agent ID (an .ai agent identity) in your wallet on BNB Chain.
  2. Publish your agent's safety policy anywhere public (a repo README is fine) and take its keccak256 hash.
  3. Connect a standard wallet (browser extension or WalletConnect) and call registerAgent(policyHash) on the ClaimGuardRegistry contract. Registration carries no protocol fee — you pay only the BNB Chain gas: one transaction of ~96,000 gas, about 0.000005 BNB at recent gas prices (well under one US cent; roughly $0.05 even if gas were 20× higher).
  4. Point your tooling at attestClaim(...) after each gate evaluation, or use the reference monitor integration in the repository.
